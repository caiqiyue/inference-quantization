# IEEE 754 与低精度浮点数基础笔记

> 面向：大模型量化初学者  
> 目标：从二进制基础出发，逐步理解 IEEE 754、FP32/FP16/BF16/FP8/FP4、浮点范围、精度、Subnormal、NaN，以及为什么这些知识是模型量化的基础。

---

# 1. 二进制整数的位权

十进制中，每一位的权重是 10 的幂：

\[
123 = 1\times10^2 + 2\times10^1 + 3\times10^0
\]

二进制完全一样，只不过底数从 10 变成了 2：

\[
101_2 = 1\times2^2 + 0\times2^1 + 1\times2^0
\]

因此：

\[
101_2 = 4 + 0 + 1 = 5
\]

所以可以记住：

- 十进制：每向左一位，权重乘 10
- 二进制：每向左一位，权重乘 2

---

# 2. 二进制小数的位权

二进制小数点右边的位权依次是：

\[
2^{-1},2^{-2},2^{-3},\cdots
\]

也就是：

\[
\frac12,\frac14,\frac18,\cdots
\]

例如：

\[
0.11_2
=
1\times2^{-1}
+
1\times2^{-2}
\]

所以：

\[
0.11_2
=
\frac12+\frac14
=
0.75
\]

再比如：

\[
1.101_2
=
1\times2^0
+
1\times2^{-1}
+
0\times2^{-2}
+
1\times2^{-3}
\]

因此：

\[
1.101_2=1+0.5+0+0.125=1.625
\]

---

# 3. 二进制乘法与小数点移动

在十进制中：

\[
1.23\times10=12.3
\]

小数点向右移动一位。

二进制中完全一样：

\[
1.11_2\times2=11.1_2
\]

因为二进制每一位的权重都是前一位的 2 倍。

验证：

\[
1.11_2=1+\frac12+\frac14=1.75
\]

乘 2：

\[
1.75\times2=3.5
\]

而：

\[
11.1_2
=
2+1+\frac12
=
3.5
\]

因此：

\[
\boxed{\text{二进制中乘 }2\text{，小数点右移一位}}
\]

同理：

\[
\boxed{\text{二进制中乘 }2^n\text{，小数点右移 }n\text{ 位}}
\]

---

# 4. 二进制科学计数法

十进制科学计数法：

\[
12300=1.23\times10^4
\]

二进制科学计数法：

\[
101.11_2
=
1.0111_2\times2^2
\]

原因是：

\[
1.0111_2\times2^2
\]

相当于将二进制小数点向右移动两位：

```text
1.0111
  ↓ × 2²
101.11
```

所以二进制科学计数法本质是：

\[
\boxed{1.xxx_2\times2^n}
\]

这就是 IEEE 754 浮点数设计的核心基础。

---

# 5. 为什么十进制 0.1 在二进制里是无限循环

十进制：

\[
0.1=\frac1{10}
\]

在十进制中能够有限表示，因为：

\[
0.1=1\times10^{-1}
\]

但是二进制小数只能由：

\[
\frac12,\frac14,\frac18,\frac1{16},\cdots
\]

组合出来。

把 0.1 转成二进制，可以不断乘 2：

```text
0.1 × 2 = 0.2   → 0
0.2 × 2 = 0.4   → 0
0.4 × 2 = 0.8   → 0
0.8 × 2 = 1.6   → 1

0.6 × 2 = 1.2   → 1
0.2 × 2 = 0.4   → 0
0.4 × 2 = 0.8   → 0
0.8 × 2 = 1.6   → 1
...
```

可以看到出现循环。

所以：

\[
0.1_{10}
=
0.000110011001100110011\cdots_2
\]

其中 `0011` 会不断循环。

本质上：

> 某个数能否在某种进制下有限表示，取决于分母约分之后是否只含该进制的质因子。

对于二进制，有限小数的分母必须最终能写成：

\[
2^n
\]

例如：

\[
\frac12,\frac14,\frac38
\]

都可以有限表示。

而：

\[
\frac1{10}
\]

因为：

\[
10=2\times5
\]

分母中还有因子 5，所以无法有限二进制表示。

这和十进制里的：

\[
\frac13=0.3333\cdots
\]

是同一个道理。

---

# 6. 为什么需要浮点数

如果所有小数都使用固定小数点，例如：

```text
前 16 bit 表示整数
后 16 bit 表示小数
```

那么表示范围会非常受限。

科学计数法可以同时表示：

- 很大的数
- 很小的数
- 一定程度的小数精度

例如：

\[
123000=1.23\times10^5
\]

\[
0.000123=1.23\times10^{-4}
\]

浮点数就是把这种思想搬到二进制中：

\[
1.xxx_2\times2^e
\]

---

# 7. IEEE 754 是什么

IEEE 754 是一套浮点数表示与计算标准。

它规定了很多内容，例如：

- 浮点数如何编码
- 符号如何表示
- 指数如何表示
- 有效数字如何表示
- 舍入规则
- 正负零
- Infinity
- NaN
- Subnormal

可以把它理解成：

> “计算机浮点数如何存、如何算”的标准规范。

---

# 8. FP32 的结构

FP32 表示：

> Floating Point 32-bit

总共 32 bit：

```text
┌──────┬──────────────┬─────────────────────────────┐
│ Sign │   Exponent   │          Fraction           │
│ 1bit │    8bit      │           23bit             │
└──────┴──────────────┴─────────────────────────────┘
```

也可以写成：

\[
S+E+F
\]

其中：

- Sign：符号
- Exponent：指数
- Fraction：小数部分 / 尾数部分

---

# 9. IEEE 754 普通浮点数公式

对于普通规格化浮点数：

\[
\boxed{
x=(-1)^S\times(1.F)\times2^{E-Bias}
}
\]

这里：

- \(S\)：符号位
- \(E\)：存储的指数编码
- \(Bias\)：指数偏置
- \(F\)：fraction
- \(1.F\)：真实有效数字

这条公式是后面理解所有浮点格式的核心。

---

# 10. Sign：符号位

符号位只有 1 bit：

```text
S = 0 → 正数
S = 1 → 负数
```

数学上：

\[
(-1)^S
\]

例如：

\[
S=0
\Rightarrow
(-1)^0=1
\]

\[
S=1
\Rightarrow
(-1)^1=-1
\]

注意：

> 浮点数整体的正负，与 exponent 的正负是两回事。

例如：

\[
-1.5\times2^{-3}
\]

这里：

- 整体是负数
- 指数也是负数

两者分别由不同机制决定。

---

# 11. Exponent：指数的意义

指数控制数值的数量级。

例如：

\[
1.5\times2^0=1.5
\]

\[
1.5\times2^5=48
\]

\[
1.5\times2^{-5}=0.046875
\]

所以指数位越多，通常能覆盖的数值范围越大。

可以记成：

\[
\boxed{\text{Exponent 主要决定 Range}}
\]

---

# 12. Fraction / Mantissa：精度的意义

假设只有 1 bit fraction：

```text
0
1
```

加上隐藏的 leading 1：

```text
1.0₂ = 1
1.1₂ = 1.5
```

如果有 2 bit fraction：

```text
00 → 1.00₂ = 1
01 → 1.01₂ = 1.25
10 → 1.10₂ = 1.5
11 → 1.11₂ = 1.75
```

可表示的数字变得更密。

所以：

\[
\boxed{\text{Fraction/Mantissa 主要决定 Precision}}
\]

---

# 13. 为什么有隐藏的 leading 1

正规化之后，一个非零二进制浮点数总可以写成：

\[
1.xxx_2\times2^e
\]

前面的 `1` 是确定的。

因此没有必要真的存下来。

例如：

\[
1.0111_2
\]

实际只存：

```text
0111...
```

前面的 `1` 在读取时自动补上。

这叫：

- hidden bit
- implicit leading 1

所以 FP32 虽然只有 23 bit fraction，但有效精度相当于约 24 bit。

---

# 14. Bias：为什么指数要加偏置

指数需要表示负数，例如：

\[
2^{-3},2^{-2},2^{-1},2^0,2^1
\]

但是 exponent 字段本身通常按无符号编码存储。

因此使用 Bias：

\[
\boxed{e=E-Bias}
\]

或者存储时：

\[
\boxed{E=e+Bias}
\]

例如 FP32：

\[
Bias=127
\]

如果真实指数：

\[
e=-3
\]

那么实际存储：

\[
E=-3+127=124
\]

这样 exponent 字段仍然只是一个非负整数。

---

# 15. Bias 为什么常写成 \(2^{k-1}-1\)

假设 exponent 有 \(k\) bit。

总共有：

\[
2^k
\]

种编码。

为了让真实指数大致围绕 0 分布，通常选：

\[
\boxed{Bias=2^{k-1}-1}
\]

例如：

## FP32

Exponent 有 8 bit：

\[
Bias=2^{7}-1=127
\]

## FP16

Exponent 有 5 bit：

\[
Bias=2^4-1=15
\]

## E4M3

Exponent 有 4 bit：

\[
Bias=2^3-1=7
\]

## E2M1

Exponent 有 2 bit：

\[
Bias=2^1-1=1
\]

本质上：

> Bias 是一种编码设计，用来把“真实指数 0”平移到 exponent 编码空间中间附近。

# 16. FP32 编码实例：5.75

现在完整推导一次。

## 第一步：十进制转二进制

\[
5=101_2
\]

\[
0.75=0.11_2
\]

因此：

\[
5.75=101.11_2
\]

## 第二步：转成二进制科学计数法

\[
101.11_2
=
1.0111_2\times2^2
\]

所以：

- Sign = 0
- 真实指数 \(e=2\)
- 有效数字 = \(1.0111_2\)

## 第三步：计算存储 exponent

FP32：

\[
Bias=127
\]

所以：

\[
E=e+127=129
\]

129 的二进制：

```text
10000001
```

## 第四步：Fraction

有效数字：

```text
1.0111
```

隐藏最前面的 `1`：

```text
01110000000000000000000
```

## 最终

```text
0 10000001 01110000000000000000000
```

这就是 5.75 的 FP32 编码。

# 17. 为什么浮点数会有误差

浮点数的 bit 数有限。

但是有些数的二进制表示是无限的，例如：

\[
0.1_{10}
=
0.0001100110011\cdots_2
\]

计算机只能保存有限位，因此需要：

```text
真实值
↓
无限二进制
↓
保留有限位
↓
舍入
↓
近似值
```

所以常见：

```python
0.1 + 0.2
```

得到类似：

```text
0.30000000000000004
```

并不是 CPU 算错了，而是：

\[
\boxed{\text{有限 bit 无法精确表示某些实数}}
\]

---

# 18. Range 与 Precision

这是后面理解低精度浮点最关键的区分。

## Range

Range 表示：

> 能覆盖多大、多小的数量级。

主要由 exponent 决定。

## Precision

Precision 表示：

> 在同一数量级中，能够把数字分得多细。

主要由 fraction / mantissa 决定。

一句话记忆：

```text
Exponent → 看得多远
Mantissa → 看得多清楚
```

---

# 19. FP32、FP16、BF16 对比

| 格式 | 总位数 | Sign | Exponent | Fraction | 特点 |
|---|---:|---:|---:|---:|---|
| FP32 | 32 | 1 | 8 | 23 | 范围大，精度高 |
| FP16 | 16 | 1 | 5 | 10 | 精度尚可，范围明显较小 |
| BF16 | 16 | 1 | 8 | 7 | 范围接近 FP32，精度较低 |

BF16 很特别：

```text
FP32  = 1 + 8 + 23
BF16  = 1 + 8 + 7
```

它保留了和 FP32 一样的 8 bit exponent。

因此：

> BF16 和 FP32 “看得差不多远”，但 BF16 “看得更模糊”。

# 20. Normal：正规数

普通正规数使用：

\[
1.F
\]

完整公式：

\[
x=(-1)^S\times(1.F)\times2^{E-Bias}
\]

例如：

\[
1.1_2\times2^2
\]

其中：

\[
1.1_2=1.5
\]

所以：

\[
1.5\times4=6
\]

---

# 21. Subnormal：次正规数

当 exponent 使用特殊的全 0 编码时，IEEE 风格浮点通常会进入 subnormal 区域。

区别是：

正规数：

\[
1.F
\]

次正规数：

\[
0.F
\]

也就是：

> 不再有隐藏的 leading 1。

作用：

> 让数值能够继续靠近 0，而不是从最小正规数直接跳到 0。

---

# 22. 0、Infinity、NaN

IEEE 754 还定义了特殊值。

## 正负零

可以存在：

```text
+0
-0
```

数学上它们都等于 0，但编码不同。

## Infinity

表示：

\[
+\infty,\quad-\infty
\]

常见于溢出或某些特殊运算。

## NaN

NaN：

> Not a Number

例如一些非法数值运算会得到 NaN。

注意：

> 并不是所有 AI 低位 FP8/FP4 格式都完全照搬 IEEE 754 的这些特殊编码规则。

# 23. FP32 最大值怎么计算

FP32：

- exponent 8 bit
- fraction 23 bit
- Bias = 127

普通数中最大的 exponent 编码通常是：

\[
E=254
\]

所以：

\[
e=254-127=127
\]

Fraction 最大：

```text
11111111111111111111111
```

有效数字：

\[
1.11111111111111111111111_2
\]

它等于：

\[
2-2^{-23}
\]

所以 FP32 最大有限值：

\[
\boxed{
(2-2^{-23})\times2^{127}
}
\]

约等于：

\[
\boxed{3.4028235\times10^{38}}
\]

---

# 24. FP32 最小正规数与最小非零数

## 最小正规数

最小 normal exponent：

\[
E=1
\]

所以：

\[
e=1-127=-126
\]

有效数字最小：

\[
1.0
\]

因此：

\[
\boxed{2^{-126}}
\]

约：

\[
1.175\times10^{-38}
\]

## 最小正非零数

利用 subnormal，还可以继续更小。

FP32 最小正非零数：

\[
\boxed{2^{-149}}
\]

约：

\[
1.4\times10^{-45}
\]

所以：

> “最小 normal” 和 “最小 non-zero” 是两回事。

---

# 25. FP8：E4M3 与 E5M2

FP8 并不是只有一种格式。

常见两类：

## E4M3

```text
1 bit Sign
4 bit Exponent
3 bit Mantissa
```

特点：

- exponent 少一些
- mantissa 多一些
- 范围相对小
- 精度相对高

## E5M2

```text
1 bit Sign
5 bit Exponent
2 bit Mantissa
```

特点：

- exponent 更多
- mantissa 更少
- 范围更大
- 精度更低

核心权衡：

\[
\boxed{\text{Exponent 与 Mantissa 在有限 bit 中竞争空间}}
\]

---

# 26. 为什么低位浮点不能只看“FP8 / FP4”

看到：

```text
FP8
FP4
```

并不能唯一确定：

- exponent 有几位
- mantissa 有几位
- Bias 是多少
- 是否保留 Inf
- 是否保留 NaN
- 是否支持 subnormal
- 最大有限值是多少

所以低精度格式必须看具体名字，例如：

```text
E4M3
E5M2
E2M1
NVFP4
MXFP4
```

# 27. FP4 E2M1 的结构

E2M1：

```text
┌────┬──────┬────┐
│ S  │ E E  │ M  │
└────┴──────┴────┘
 1      2      1
```

总共：

\[
1+2+1=4
\]

4 bit 总共有：

\[
2^4=16
\]

种 bit pattern。

Bias：

\[
Bias=2^{2-1}-1=1
\]

---

# 28. FP4 E2M1 为什么会出现 1 和 1.5

M 只有 1 bit：

```text
M = 0
M = 1
```

对于 normal：

```text
M = 0 → 1.0₂
M = 1 → 1.1₂
```

而：

\[
1.0_2=1
\]

\[
1.1_2
=
1+\frac12
=
1.5
\]

所以 E2M1 在同一个 exponent 下，只能使用：

\[
\boxed{1,\quad1.5}
\]

这说明 mantissa 非常粗糙。

没有隐藏的 leading 1。

\]

得到：

0.1_2=0.5

0.5
\]

E=1
\]

e=1-1=0

1.0\times2^0=1

\[
1.5\times2^0=1.5
\]

得到：

\[
1,\ 1.5
\]

## E = 10

\[
E=2
\]

真实指数：

\[
e=2-1=1

\[
1.5\times2^1=3
\]

得到：

\[
2,\ 3
\]

## E = 11

在这种 E2M1 设计中继续用于有限数。

\[
E=3
\]

真实指数：

\[

\]

### M = 0

\[
1\times2^2=4

\[

# 30. FP4 E2M1 的可表示值

正数部分：

\[
\boxed{
0,\ 0.5,\ 1,\ 1.5,\ 2,\ 3,\ 4,\ 6
}
\]

加上 Sign：

\[
\boxed{
-6,-4,-3,-2,-1.5,-1,-0.5,-0,+0,+0.5,+1,+1.5,+2,+3,+4,+6
}
\]

由于 `+0` 和 `-0` 数学上相同：

> 16 个 bit pattern 不一定意味着 16 个不同数学数值。

---

# 31. 为什么 FP4 不能表示 1.2

FP4 E2M1 的相邻候选值可能是：

```text
1
1.5
```

但没有：

```text
1.1
1.2
1.3
1.4
```

因此原始值：

\[
1.2
\]

必须被近似为可表示值。

例如按最近值舍入：

\[
1.2\rightarrow1.0
\]

这就是：

\[
\boxed{\text{表示误差 / 量化误差}}
\]

---

# 32. 为什么 FP4 的数值间隔越来越大

FP4 E2M1：

```text
0 → 0.5 → 1 → 1.5 → 2 → 3 → 4 → 6
```

间隔：

```text
0.5
0.5
0.5
0.5
1
1
2
```

为什么？

因为 exponent 增大之后：

\[
2^e
\]

会放大整个有效数字区间。

所以：

> 浮点数并不是均匀刻度。

数值越大，绝对间距通常也会变大。

---

# 33. Fraction bit 越多为什么精度越高

假设 M1：

```text
1.0
1.5
```

只有两个刻度。

M2：

```text
1.00 = 1
1.01 = 1.25
1.10 = 1.5
1.11 = 1.75
```

M3：

```text
1.000 = 1
1.001 = 1.125
1.010 = 1.25
1.011 = 1.375
1.100 = 1.5
...
```

可以看到：

\[
\boxed{\text{Mantissa bit 越多，数字间隔越小}}
\]

所以精度更高。

# 34. 为什么 FP4 / FP8 对大模型仍然有价值

如果直接让 FP4 表示模型权重，问题非常明显。

例如原始权重：

```text
0.12
0.83
1.26
2.73
5.41
```

FP4 可能只能近似成：

```text
0
1
1.5
3
6
```

误差很大。

因此现代大模型量化不会简单地说：

> “直接把所有真实权重塞进 FP4。”

而是引入：

\[
\boxed{Scale}
\]

# 35. Scale 的基本思想

假设：

\[
scale=0.001
\]

真实权重：

\[
0.003
\]

可以先除以 scale：

\[
q=\frac{0.003}{0.001}=3
\]

FP4 只需要保存：

\[
q=3
\]

恢复时：

\[
W\approx q\times scale
\]

得到：

\[
3\times0.001=0.003
\]

所以：

\[
\boxed{
W\approx q\times scale
}
\]

这是模型量化最核心的思想之一。

# 36. 为什么还需要 Block / Group Scaling

假设整个模型中的权重范围差异很大：

```text
0.0001
0.01
1
100
```

如果整个模型只共享一个 scale：

- 小数值可能全部挤在一起
- 大数值又可能溢出

所以现代量化经常：

```text
一小组权重 → 一个 scale
另一小组权重 → 另一个 scale
...
```

例如：

```text
32 个权重
↓
共享一个 scale
```

这就是：

- Block Quantization
- Group Quantization
- Block Scaling

等机制的基础思想。

# 37. 与大模型显存的关系

不同数值格式直接影响模型权重存储。

假设 7B 模型，仅粗略计算权重：

## FP32

\[
7\times10^9\times4Byte
\approx28GB
\]

## FP16 / BF16

\[
7\times10^9\times2Byte
\approx14GB
\]

## INT8 / FP8

\[
7\times10^9\times1Byte
\approx7GB
\]

## INT4 / FP4

\[
7\times10^9\times0.5Byte
\approx3.5GB
\]

实际运行显存通常还包括：

- KV Cache
- 激活值
- CUDA buffer
- 临时张量
- 框架运行时开销

所以不能简单认为模型显存只等于权重大小。

# 41. 一句话总结

IEEE 754 的核心不是“记住 FP32 有多少 bit”，而是理解：

\[
\boxed{
\text{有限 bit}
\rightarrow
\text{有限范围和有限精度}
\rightarrow
\text{必须做数值近似}
}
\]

而大模型量化，本质上就是进一步主动利用这种数值近似：

> 用更少的 bit 表示模型中的权重和激活，在尽量保持模型效果的前提下，降低显存、带宽和计算成本。
