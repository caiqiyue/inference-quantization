那基本可以确定了，你昨天听到的应该是浮点数计算中的几个核心概念：

* **对阶（Exponent Alignment）**：浮点数相加前，需要把两个数调整到相同的指数。
* **阶差（Exponent Difference）**：两个浮点数的指数相差多少。
* **尾数右移与精度丢失**：对阶过程中，较小数的尾数需要右移，部分有效数字可能被移出可保留的范围。
* **舍入（Rounding）**：由于尾数位数有限，计算机需要按照规定的规则保留或舍弃多余的位。
* **大数吃小数**：当两个浮点数的数量级相差很大时，较小的数可能完全无法影响最终计算结果。

你听到的“阶误差”，可能是“阶差”或者“对阶误差”。

其中，**对阶导致的精度损失，是理解浮点数计算误差非常重要的一环**。

我们直接用一个例子把这些概念串起来。

# 一、先思考：为什么计算机可能算不出 16 + 1？

正常情况下：

\\[ 16+1=17 \\]但假设我们设计了一种简化的二进制浮点数，它的有效数字只能保留 **4 位**。

注意，这是假设的教学格式，不是标准 FP4 E2M1。

对于这种浮点数：

\\[ 16=1.000\_2\\times2^4 \\]\\[ 1=1.000\_2\\times2^0 \\]两个数都可以精确表示。

那么问题来了：

**两个数单独都能精确表示，为什么相加后的结果却可能不准确？**

原因就藏在对阶和舍入过程中。

---

# 二、第一步：对阶——将指数调整到相同

我们先观察两个数：

\\[ A=1.000\_2\\times2^4 \\]\\[ B=1.000\_2\\times2^0 \\]它们的指数分别为：

\\[ e\_A=4,\\qquad e\_B=0 \\]所以阶差为：

\\[ \\Delta e=4-0=4 \\]为了执行加法，需要将指数对齐。

通常做法是保留较大数的指数，将较小数的尾数右移。

原本：

\\[ B=1.000\_2\\times2^0 \\]改写成：

\\[ B=0.0001\_2\\times2^4 \\]于是：

\\[ A+B=(1.000\_2+0.0001\_2)\\times2^4 \\]数学上没有任何问题。

但是，我们设计的浮点格式只能保留 4 位有效数字。

注意：

```
A 的有效数字：

1.000
^^^^
4 位


B 对阶后的有效数字：

0.0001
    ^
    这个 1 已经落在可保留精度之外
```

这里需要理解：

**对阶本身是数学上的等价变换，并不会造成误差；真正的误差来自有限精度表示过程中对移出位的舍入或舍弃。**

---

# 三、第二步：尾数相加，发生精度损失

理论上：

```
  1.0000
+ 0.0001
--------
  1.0001
```

所以：

\\[ 16+1=1.0001\_2\\times2^4=17 \\]但有效数字只允许保留 4 位。

因此，结果 `1.0001` 无法完整保存。

按照常用的 IEEE 754 默认舍入模式：

**Round to Nearest, Ties to Even（最近舍入，遇到正中间取偶数）**

17 恰好位于两个相邻可表示数字 16 和 18 的中间。

最终选择：

\\[ \\boxed{\\operatorname{fl}(16+1)=16} \\]其中 \\(\\operatorname{fl}\\) 表示在指定浮点格式和舍入模式下得到的结果。

也就是说：

\\[ \\boxed{16+1=16\\quad\\text{（在这个简化浮点格式中）}} \\]这就是浮点数的精度损失。

但这里有个细节需要特别注意：如果使用不同舍入模式，比如向正无穷方向舍入，结果可能是 18，而不是 16。

所以计算机并不是简单地把所有多余位直接截掉。

---

# 四、什么叫“大数吃小数”？

我们继续使用这个只有 4 位有效数字的浮点格式。

假设：

\\[ A=16 \\]分别加上几个不同的小数。


| 计算     | 精确结果 | 浮点计算结果（最近舍入、遇中取偶） |
| -------- | -------- | ---------------------------------- |
| 16 + 0.5 | 16.5     | 16                                 |
| 16 + 1   | 17       | 16                                 |
| 16 + 2   | 18       | 18                                 |
| 16 + 4   | 20       | 20                                 |

为什么？

因为在 16 附近，这种浮点格式只能表示：

\\[ 16,\\ 18,\\ 20,\\ 22,\\ 24,\\ldots \\]无法表示它们之间的所有实数。

因此：

\\[ 16+0.5=16.5 \\]最终只能舍入为 16。

当小数足够小的时候，加法结果甚至完全不发生变化。

这就是常说的：

**大数吃小数（Swamping）**。

它不是说小数没有参与运算，而是说小数对精确结果的贡献，无法体现在最终有限精度的表示中。

---

# 五、这和 BF16、FP32 有什么关系？

你现在做 llama.cpp 量化，经常遇到 BF16、FP32 和 FP8。

它们的有效精度差异非常大。


| 格式     | 指数位 | 显式尾数字段 | 规格化数有效精度 |
| -------- | ------ | ------------ | ---------------- |
| FP32     | 8 bit  | 23 bit       | 24 bit           |
| BF16     | 8 bit  | 7 bit        | 8 bit            |
| FP16     | 5 bit  | 10 bit       | 11 bit           |
| FP8 E4M3 | 4 bit  | 3 bit        | 通常为 4 bit     |
| FP4 E2M1 | 2 bit  | 1 bit        | 通常为 2 bit     |

这里的有效精度，对于正常的规格化二进制浮点数，还包含一个隐含的最高有效位。

**为什么 BF16 和 FP32 的指数位都是 8 bit，但是计算精度差别很大？**

因为它们的尾数精度不同。

例如，在 256 附近：

BF16 的相邻规格化浮点数间隔为：

\\[ 2^{8-(8-1)}=2 \\]所以：

\\[ 256+1 \\]在 BF16 最近舍入、遇中取偶的规则下，结果为：

\\[ 256 \\]而 FP32 的有效精度有 24 bit，能够精确表示 257：

\\[ 256+1=257 \\]这就解释了为什么：

**BF16 虽然拥有和 FP32 接近的数量级范围，但数值精度远低于 FP32。**

指数位更多，主要影响能够表示的数值范围；尾数位更多，主要影响同一数量级下可区分的数值精细程度。

---

# 六、为什么大模型经常使用 FP32 累加？

现在将刚才的知识放回你的 NVFP4 矩阵乘法。

假设：

\\[ Y=\\sum\_{i=1}^{K}X\_iW\_i \\]这个点积过程包含大量乘法和加法。

例如：

\\[ Y=16+1+1+1+1 \\]数学上的结果：

\\[ Y=20 \\]但如果使用前面那个只有 4 位有效数字的浮点格式，并且每次加法都进行舍入：

```
初始：16

16 + 1 = 16

16 + 1 = 16

16 + 1 = 16

16 + 1 = 16
```

最终：

\\[ Y\_{\\mathrm{low}}=16 \\]误差：

\\[ 20-16=4 \\]但如果乘积能够精确转换到 FP32，随后使用 FP32 累加：

\\[ 16+1+1+1+1=20 \\]这个例子中就不会发生误差。

这就是为什么大模型低精度矩阵计算经常采用：

\\[ \\boxed{\\text{低精度输入}+\\text{较高精度累加}} \\]例如：

* FP16 × FP16，使用 FP32 累加。
* BF16 × BF16，使用 FP32 累加。
* 一些 NVFP4 矩阵计算路径使用更高精度的累加器。

不过，**使用 FP32 累加不等于完全没有累加误差**。FP32 的有效精度仍然有限，而且具体硬件可能采用分组累加、分阶段舍入等实现。

---

# 七、这里还隐藏着一个重要知识：浮点加法不满足结合律

你在以后做数值误差定位时，经常会遇到：

“同样的数据，为什么换了计算顺序，结果就不一样？”

根本原因之一就是浮点加法一般不满足数学上的结合律。

即：

\\[ (a+b)+c \\]与：

\\[ a+(b+c) \\]在浮点计算中不一定相等。

我们还用前面 4 位有效精度的例子：

\\[ a=16,\\quad b=1,\\quad c=1 \\]第一种顺序：

\\[ (16+1)+1 \\]因为：

\\[ 16+1\\rightarrow16 \\]所以：

\\[ 16+1\\rightarrow16 \\]最终：

\\[ \\boxed{16} \\]第二种顺序：

\\[ 16+(1+1) \\]先计算：

\\[ 1+1=2 \\]再计算：

\\[ 16+2=18 \\]得到：

\\[ \\boxed{18} \\]于是：

\\[ \\boxed{(16+1)+1\\neq16+(1+1)} \\]虽然在数学上两者都应该是 18。

这也是为什么不同 GPU Kernel、不同线程归约方式、不同累加顺序可能得到略有差异的结果。

对于你现在研究的 NVFP4 量化误差，这一点尤其值得注意。

因为有时你看到的输出差异，并不完全来自 FP4 数值映射，也可能来自累加顺序和中间计算精度。

---

# 八、最后，把昨天听到的几个概念串起来

你可以把浮点数加法理解成下面的过程：

```
输入两个浮点数
       │
       ▼
拆分符号、指数、有效数字
       │
       ▼
计算阶差
       │
       ▼
对阶（较小指数一侧右移）
       │
       ▼
有效数字加减
       │
       ▼
结果规格化
       │
       ▼
根据舍入规则保留有效数字
       │
       ▼
得到浮点计算结果
```

其中最值得记住的三个结论是：

**第一，对阶不是误差本身。**

对阶是为了让不同数量级的浮点数能够进行加减。有限精度的移位、计算和舍入才可能造成精度损失。

**第二，阶差越大，较小的数越可能被舍入掉。**

因为指数差距越大，较小数的有效位就需要移动得越远，越容易落到结果无法保留的位置。

**第三，低精度输入与低精度累加是两个不同的问题。**

即使输入已经量化成 FP4，仍然可以使用较高精度的计算路径减少额外的计算误差。

## 最后给你一个很有价值的问题

假设一个点积：

\\[ Y=10000+0.01+0.01+0.01+\\cdots \\]后面有 1000 个 \\(0.01\\)。

数学上：

\\[ Y=10010 \\]但如果采用有限精度浮点数，从左到右逐个累加，这些 \\(0.01\\) 可能在过程中不断被舍入，导致最终结果偏小。

那么，你觉得：

**如果先把 1000 个 0.01 加起来，最后再加 10000，为什么有可能得到更准确的结果？**

这个问题能够帮助你真正理解：为什么矩阵乘法的累加顺序、累加精度，以及 GPU Kernel 的实现方式都会影响最终数值结果。



对！**浮点数能够保留多少位有效数字，主要就是由尾数（Mantissa，也常称 Significand）部分的位数决定的。**

不过，这里有一个非常重要、也很容易混淆的细节：

**对于 IEEE 754 的规格化二进制浮点数，有效数字的位数通常 = 尾数字段位数 + 1。**

为什么要加 1？我们从 FP32 的结构讲起。

## 一、浮点数由三个部分组成

以 FP32 为例，总共 32 bit：


| 符号位（Sign） | 指数位（Exponent） | 尾数字段（Fraction） |
| -------------- | ------------------ | -------------------- |
| 1 bit          | 8 bit              | 23 bit               |
| 决定正负       | 决定数值范围       | 决定数值精度         |

对于正常的规格化浮点数，其计算公式为：

\\[ \\boxed{x=(-1)^s\\times(1.m)\_2\\times2^{E-\\text{Bias}}} \\]其中：

* \\(s\\)：符号位。
* \\(E\\)：存储的指数编码。
* Bias：指数偏置，FP32 为 127。
* \\(m\\)：存储的尾数字段。
* \\(1.m\\)：真正参与计算的有效数字。

重点就在这里：

### 为什么尾数只有 23 bit，却有 24 bit 有效精度？

因为规格化二进制浮点数的有效数字，最高位必然是 1。

例如：

\\[ 1.101101\_2\\times2^3 \\]最前面的 `1` 不需要额外存储。

硬件只需要保存：

```
真实有效数字：1.101101
             ↑
             隐含的 1

实际存储：     101101...
```

因此，FP32 虽然只保存 23 位尾数字段，但实际上具有：

\\[ \\boxed{23+1=24\\text{ bit 有效精度}} \\]这个不存储但隐含存在的 `1`，通常叫 **Hidden Bit（隐藏位）**。

注意，非规格化数（Subnormal）没有这个隐含的前导 1，其有效精度会有所降低。

---

## 二、为什么我们前面的例子只保留 4 位有效数字？

因为前面为了方便手工推导，**人为假设了一种只有 4 bit 有效精度的浮点格式**。

这意味着：

* 1 bit 隐含的整数部分。
* 3 bit 存储的尾数部分。

例如：

\\[ 16=1.000\_2\\times2^4 \\]其中：

```
1 . 0 0 0
↑   └─┬─┘
│     │
│     └── 3 bit 尾数字段
│
└──────── 1 bit 隐含位
```

所以总共是：

\\[ 1+3=4\\text{ bit} \\]因此能够保留：

\\[ 1.000\_2 \\]却无法精确保留：

\\[ 1.0001\_2 \\]因为后者需要 5 bit 有效精度。

回到前面的计算：

\\[ 16+1=17 \\]二进制表示为：

\\[ 17=10001\_2=1.0001\_2\\times2^4 \\]但是只有 4 bit 有效精度：

```
精确结果：

1.0001
│   │
│   └── 第 5 位，无法保存
│
└────── 前 4 位有效数字


可保存：

1.000
```

使用最近舍入、遇中取偶：

\\[ 17\\rightarrow16 \\]所以：

\\[ \\boxed{\\operatorname{fl}(16+1)=16} \\]这就是为什么前面的例子会出现“大数吃小数”。

---

## 三、尾数位越多，精度就越高吗？

是的，通常如此。

我们用 16 附近的可表示数值来比较。


| 浮点格式 | 尾数字段 | 有效精度 | 16 附近相邻数值的间隔 |
| -------- | -------- | -------- | --------------------- |
| 教学格式 | 3 bit    | 4 bit    | 2                     |
| BF16     | 7 bit    | 8 bit    | 0.125                 |
| FP16     | 10 bit   | 11 bit   | 0.015625              |
| FP32     | 23 bit   | 24 bit   | 约 0.000001907        |

为什么会出现这样的差异？

对于一个具有 \\(p\\) 位有效精度的二进制浮点格式，在区间：

\\[ [2^e,2^{e+1}) \\]相邻规格化浮点数的间距通常是：

\\[ \\boxed{\\mathrm{ULP}=2^{e-(p-1)}} \\]ULP（Unit in the Last Place）可以理解为：**当前数值附近，相邻两个可表示浮点数之间的距离。**

以教学格式为例：

\\[ p=4,\\quad e=4 \\]因此：

\\[ \\mathrm{ULP}=2^{4-3}=2 \\]所以 16 附近只能表示：

\\[ 16,\\ 18,\\ 20,\\ 22,\\ldots \\]但对于 BF16：

\\[ p=8 \\]\\[ \\mathrm{ULP}=2^{4-7}=0.125 \\]于是 BF16 能表示：

\\[ 16,\\ 16.125,\\ 16.25,\\ 16.375,\\ldots \\]这就是尾数位数决定数值精细程度的具体体现。

---

## 四、那么指数位又有什么作用？

这是你需要和尾数位区分开的。

**指数位主要决定数值能表示多大、多小；尾数位主要决定同一数量级附近的表示精度。**

例如：


| 格式     | 指数位 | 尾数字段 | 有效精度 |
| -------- | ------ | -------- | -------- |
| FP32     | 8      | 23       | 24       |
| BF16     | 8      | 7        | 8        |
| FP16     | 5      | 10       | 11       |
| FP8 E4M3 | 4      | 3        | 4        |
| FP4 E2M1 | 2      | 1        | 2        |

你现在做的 NVFP4，采用 E2M1 格式。

这意味着，对于规格化数：

\\[ \\boxed{\\text{有效精度}=1+1=2\\text{ bit}} \\]也就是只有 2 bit 有效数字！

因此 FP4 E2M1 本身可以表示的数字非常有限。

这也解释了为什么 NVFP4 需要引入 Block Scale 和 Global Scale：通过缩放，使这些有限的 FP4 数值能够覆盖不同幅度的数据。

但要注意：

**Scale 能改变 FP4 可表示数值的范围和间隔，却不能凭空增加 FP4 尾数本身的有效位数。**

例如：

\\[ x=q\_{\\mathrm{FP4}}\\times s \\]不同的 Scale 可以让同一个 FP4 编码代表不同的原始数值，但一个固定 Scale 下仍然只有有限的量化档位。

---

## 五、你现在应该建立的核心认知

对于二进制浮点数：

\\[ \\boxed{\\text{数值}=(-1)^{\\text{符号}}\\times\\text{有效数字}\\times2^{\\text{指数}}} \\]三个部分各司其职：

* **符号位：** 正还是负。
* **指数位：** 数值位于什么数量级。
* **尾数字段：** 在这个数量级下能够精确区分哪些数值。

以后你听到“对阶”“尾数右移”“舍弃低位”“舍入误差”，就应该联想到：

**浮点加法需要将两个数调整到相同指数，而尾数精度有限，因此一些较低的有效位可能无法保留下来。**

最后我给你一个小问题，帮助你进一步理解：

假设仍然使用只有 4 bit 有效精度的教学格式：

\\[ A=16,\\quad B=2 \\]我们之前知道：

\\[ 16+1\\rightarrow16 \\]那么：

\\[ 16+2 \\]最终会得到 16、18，还是 20？

你可以尝试从二进制的 `1.000 × 2⁴` 开始，自己完成一次对阶和尾数相加。
